# ai-prd-workflow 治理待办

这份文档用于记录在真实需求交付过程中暴露出来、但当下不一定立刻修改 skill 的问题。

它不是某个具体需求的交付物，也不是用户侧文档，而是仓库版 `ai-prd-workflow` 的持续演进待办池。目标是把“项目中发现的 skill 不足”显式沉淀下来，避免问题只停留在对话里，或每次重复踩坑。

## 使用原则

- 只记录会重复影响后续需求交付的问题。
- 优先记录 workflow、目录结构、模板、边界、检查清单、入口约束等顶层问题。
- 每条待办应说明：问题是什么、影响什么、建议怎么改、当前状态是什么。
- 需求交付过程中如果发现 skill 不足，但当前项目不适合立刻改 skill，先记到这里，项目结束后再统一治理。

## 状态定义

- `待处理`：问题已确认，但还未开始改 skill。
- `处理中`：已经开始修改 skill 或补充规范。
- `已完成`：已同步进仓库版 skill，并且相关文档或流程已更新。
- `已放弃`：确认不进入 skill，或判断不值得治理。

## 处理建议

建议每次改 skill 时，先过一遍这张表：

1. 判断哪些问题已经成熟到可以正式进入 skill。
2. 优先处理会影响所有新需求启动质量的问题。
3. 完成后同步更新对应文档、模板或 `SKILL.md`。
4. 若某条已落地，更新状态并补充变更说明。

## 与其他文档的关系

- `docs/`：面向仓库维护者，承接使用说明、治理待办、维护规则。
- `skills/ai-prd-workflow/shared/references/`：面向 skill 运行时引用的标准与规范。
- `skills/ai-prd-workflow/SKILL.md`：只保留顶层工作流和关键约束，不承载大段治理 backlog。
