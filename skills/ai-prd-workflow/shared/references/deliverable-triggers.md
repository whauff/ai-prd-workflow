# 交付物触发条件

按内容触发交付，不按模板习惯堆交付。

## 什么时候出原型

- 页面、表单、状态或交互行为本身会影响评审结论。
- 交互状态本身很重要。
- 大概率会在界面或行为上产生分歧。

## 什么时候不出原型

- 页面只是承载内容，评审分歧不在界面或交互。
- PRD 已经能清楚表达范围、状态、字段和验收。
- 新增原型只会重复 PRD，不会暴露新的判断问题。

## 什么时候出规则稿

- 需求包含复杂业务规则口径。
- 规则需要独立评审、复用或持续维护。
- 规则存在多条件组合、多主体差异、多场景适配、优先级或例外情况。
- 放在 PRD 中会让正文复杂、难评审。

地址治理、状态检查、识别校验类需求，不因“有规则”就默认出规则稿。

## 什么时候出流程图

- 逻辑包含关键分支。
- 有保存前或保存后的处理。
- 存在同步、解析、回写或异常链路。
- 文字已经开始不如图示清楚。

## 什么时候停止扩产物

- 核心问题、目标和方案已经清楚。
- 当前对象已有足够材料。
- 没有新增分歧。
- 新增交付物只会重复已有内容。
