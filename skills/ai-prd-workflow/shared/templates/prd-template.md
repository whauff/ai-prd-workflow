# PRD 模板

这是一份最小可用 PRD 模板。不要强行把每一章都写长。未命中的章节可以跳过。原型已经表达清楚的内容，不要再翻译成大段填充文字。若规则已经成为协作重点，应拆成独立规则稿，正文只保留简要摘要。

## 1. 背景

说明当前问题、现状，以及为什么现在要做。

## 2. 目标

说明预期业务结果，以及如何判断这次需求是否达成。

## 3. 用户与场景

说明谁会受到影响，以及这个需求在哪些场景下成立。

## 4. 方案概述

尽量简短地概述这次准备怎么做。

## 5. 交互与页面

只在页面、表单、状态或交互变化确实重要时展开。

## 6. 规则与治理

只在存在识别、拦截、打标、评分或边界规则时使用。如果规则系统较复杂，应链接到独立规则稿，而不是在这里全部展开。

## 7. 验收标准

说明满足什么条件后，这次需求可以视为完成。

## 8. 风险与待确认

只列出真正尚未收敛的问题。不要为了完整而凑内容。
