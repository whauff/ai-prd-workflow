# Mobile Business Page

Use this reference when refining mobile, mini-program, employee-side, store-side, doctor-side, or other mobile work pages.

The goal is not to copy one visual style. The goal is to make mobile business prototypes feel like real task pages: clear, light, actionable, and free of review-only explanation.

## Applicable Pages

- Training, learning, task, checklist, status, result, and progress pages
- Mobile forms, detail pages, empty states, result states, and operation feedback
- Employee, store, doctor, or service-side pages where users complete lightweight work

Do not use this as a marketing, campaign, content feed, or brand-heavy visual template.

## Structure Principles

- Put the user's current task first: what this page is about, current state, and next action.
- Use stable module titles. A module title expresses responsibility, not the current result.
- Keep status, result, explanation, and action in separate layers.
- Prefer a short main path over many equal choices.
- Use fixed bottom actions when the decision or operation is central to the page.
- Keep secondary information below or quieter; do not let metadata compete with the primary task.

## Page Body Admission

Only keep content in the mobile page body if the real user needs it to decide or act.

Keep:

- Current state, progress, result, key fields, next action, and necessary operation feedback
- Short reason or next-step guidance when the user cannot infer it from the state or button

Move or delete:

- Review reminders
- Rule explanations
- "Why this design" explanations
- Long background context
- Repeated explanations of a visible status, title, or button

## Visual And Interaction Rules

- Use mobile-native density: readable text, compact cards, clear tap targets, and stable vertical rhythm.
- Do not shrink a desktop backend page into a phone.
- Primary action should be visually obvious and singular when possible.
- Clickable text should look clickable; ordinary labels should not look like links.
- Status tags should be visible but not louder than the page title or primary action.
- Cards are for grouping task information, not for wrapping every sentence.
- Empty, disabled, completed, blocked, expired, and no-permission states need distinct visible expression.

## Copy Rules

- Prefer short labels and action verbs.
- Avoid explaining what the user can already see.
- Avoid "当前只需", "不需要", "用于评审", and similar review-driven wording unless it is real user guidance.
- If the right-side review note already explains a rule, do not move that explanation into the mobile page body.

## Review Questions

- Would a real mobile user need every sentence on this screen?
- Can the user identify the current state and next action within a few seconds?
- Are module titles stable across result states?
- Does any page body copy exist only because the reviewer might be confused?
- Does the page still work with long names, empty data, completed state, blocked state, and no-permission state?
