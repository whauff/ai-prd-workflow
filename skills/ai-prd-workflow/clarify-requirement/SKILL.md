# clarify-requirement

只做需求澄清，不生成 PRD、原型、流程图或技术方案。

## 目标

- 补齐关键缺口。
- 整理结构化摘要。
- 判断下一阶段：Brief 或 PRD。

## 输入

可以接受以下任意一种或多种输入：

- 一句话需求
- 聊天记录
- 会议纪要
- 页面截图
- 样本、案例、数据说明

## 工作方式

1. 先阅读 [../shared/references/context-checklist.md](../shared/references/context-checklist.md)。
2. 只追问影响方案方向的缺口。
3. 不重复已知信息。
4. 信息足够时，直接输出摘要。
5. 样本影响判断口径时，指出缺失样本。
6. 需确认范围、顺序、字段、权限或边界时，建议进入 Brief。

## 输出格式

输出四部分：

### 1. 已知信息

- 背景
- 目标
- 用户
- 场景
- 现状
- 成功标准

### 2. 待确认问题

- 只列影响方案方向的问题
- 优先列 2 到 5 个

### 3. 结构化需求摘要

- 问题是什么
- 为什么现在要做
- 谁会使用
- 用户在什么场景下使用
- 成功的判断标准是什么

### 4. 阶段判断

- 可进入 PRD
- 建议先进入 Brief
- 仍需补充信息

## 边界

- 不输出技术设计。
- 不拆研发任务。
- 不追问无关信息。
