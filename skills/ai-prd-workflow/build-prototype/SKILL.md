# build-prototype

只做产品交付原型，用于帮助团队看清页面结构、关键状态和交互路径。

## 前提

只有在以下条件至少满足大部分时才进入本 skill：

- 需求目标已经基本清楚
- 核心用户和场景已经清楚
- 主要页面或关键操作路径已经有初步定义

如果连要做什么页面都不清楚，应先回到需求澄清或 PRD 阶段。

## 读取文件

开始产出前按需读取：

- [../shared/references/prototype-guidelines.md](../shared/references/prototype-guidelines.md)
- [../shared/references/reduction-checklist.md](../shared/references/reduction-checklist.md)

如果 PRD 已存在，应优先基于现有 PRD，而不是脱离上下文重新发明界面。

## 工作方式

1. 只覆盖会影响评审结论的关键页面和关键状态。
2. 优先表达主流程、异常状态、空状态和关键反馈。
3. 原型应服务业务评审，不追求炫技或通用组件体系。
4. 如果某段内容用 PRD 已经讲清楚，就不要在原型里重复堆说明。
5. 如需假数据或占位内容，保持真实业务感，但不要伪装成最终文案。

## 输出

输出应至少包含：

- 原型覆盖了哪些页面或场景
- 原型未覆盖哪些内容
- 关键状态说明
- 与 PRD 是否存在需要同步更新的差异

## 边界

- 不写技术实现方案。
- 不扩展到设计系统建设。
- 不为了美观而牺牲评审效率。
- 不把原型当成正式开发代码承诺。
